## 1. Архитектура и состав прототипа (Модуль 3)

Прототип реализует четырёхуровневую модульную архитектуру ИИС и поддерживает два режима работы:
1. **Полный клиент-серверный режим (Python REST API + Реляционная БД 14 таблиц + ИИ-модуль `scikit-learn`)**:
   - `backend/server.py` — HTTP-сервер и маршрутизатор REST API (16 конечных точек `/api/v1/*`), раздающий клиентское SPA-приложение и обрабатывающий запросы телеметрии, аналитики, рекомендаций, ролевой авторизации, инспектора БД и адаптации ИИ.
   - `backend/ai_engine.py` — гибридный интеллектуальный модуль (`EnergoAIEngine`), объединяющий детерминированные правила предметной области и ансамблевую регрессионную модель `GradientBoostingRegressor` (`scikit-learn`), вектор объяснимости **XAI** и контур контролируемой адаптации $Model_{t+1} = Update(Model_t, Data_{new})$.
   - `backend/db_manager.py` — менеджер реляционной базы данных (`DatabaseManager`), автоматически создающий и инициализирующий все **14 таблиц в 3НФ** (`roles`, `users`, `rooms`, `room_controllers`, `workstations_devices`, `schedule_slots`, `system_settings_tariffs`, `telemetry_measurements`, `ml_models`, `ai_evaluation_runs`, `energy_forecasts`, `detected_anomalies`, `saving_recommendations`, `system_events_log`) в полном соответствии со скриптом `schema.sql` для целевой СУБД PostgreSQL 16 и локальным движком SQLite 3.
   - `backend/validators.py` — модуль валидации физических границ телеметрии и полей БД (`VALIDATION_BOUNDS`), санитизации строк от XSS (`html.escape`), фильтрации SQL-запросов (разрешены только одиночные `SELECT` и `PRAGMA table_info`) и ролевого разграничения доступа (RBAC) с выдачей случайных сессионных токенов.
2. **Автономный браузерный демо-режим (GitHub Pages / `localStorage`)**:
   - `index.html`, `styles.css`, `model.js`, `app.js` — адаптивный веб-интерфейс из 7 разделов («Обзор кампуса», «Кабинеты», «Аналитика», «Журнал событий», «База данных», «Настройки и датчики», «О проекте»), автоматически синхронизирующийся с `/api/v1/*` при наличии запущенного Python-сервера и бесшовно переключающийся на локальную модель `EnergyModel` и `localStorage` при открытии на GitHub Pages (в автономном режиме в инспекторе БД отображаются 2 таблицы — `rooms` и `system_settings_tariffs`).

> **Честная маркировка данных:** Все временные ряды нагрузки, расписания и телеметрии в прототипе являются **синтетическими демонстрационными данными** (`is_synthetic = true`) для 6 учебных кабинетов (`201`, `202`, `204`, `301`, `302`, `305`, суммарно 72 ПК) и не выдаются за коммерческие измерения физических счётчиков.

## 2. Инструкция по установке и запуску

### Требования к окружению
- **ОС:** Windows 10/11, Linux или macOS
- **Python:** версия 3.11+ (проверено на Python 3.14) с библиотеками `numpy` и `scikit-learn`
- **СУБД:** встроенный движок `sqlite3` (запускается автоматически без внешней настройки; файл `energocampus_demo.sqlite3`); для целевой промышленной СУБД `PostgreSQL 16+` подготовлены скрипты `schema.sql` и `seed_demo_data.sql`

### Шаг 1. Установка зависимостей Python
```powershell
pip install -r requirements.txt
```

### Шаг 2. Настройка паролей ролей через переменные окружения (без хранения в коде)
В публичных файлах репозитория пароли не хранятся. Для задания собственных паролей ролей **Энергетика** (`energomanager`) и **Системного администратора** (`sys_admin`) перед запуском сервера установите переменные окружения в PowerShell (или создайте локальный файл `.env` по образцу `.env.example`):
```powershell
$env:ENERGOCAMPUS_PASS_MANAGER = "ваш_пароль_энергетика"
$env:ENERGOCAMPUS_PASS_ADMIN = "ваш_пароль_администратора"
```

### Шаг 3. Запуск полного серверного контура ИИС (Backend + БД + ИИ + Frontend)
Из папки `energocampus_app` выполните:
```powershell
py -m backend.server
```
(или запустите интерактивный лаунчер `py run_all_in_one.py` / `START.bat`).
После запуска сервер выведет сообщение:
```text
[ЭнергоКампус] Сервер ИИС запущен: http://127.0.0.1:8000
[ЭнергоКампус] Реляционная БД (14 таблиц): ...\energocampus_demo.sqlite3
[ЭнергоКампус] Активная модель ИИ: v1.2-gbr (Hybrid Rule-Based + scikit-learn GradientBoostingRegressor)
```
Откройте в браузере адрес **http://127.0.0.1:8000**.

### Шаг 4. Развёртывание схемы в целевой СУБД PostgreSQL 16 (опционально)
Для развёртывания базы данных на выделенном сервере PostgreSQL 16 выполните:
```powershell
psql -U postgres -d energocampus_db -f schema.sql
psql -U postgres -d energocampus_db -f seed_demo_data.sql
```

### Шаг 5. Запуск автоматизированных тестов (22 тест-кейса TC-01..TC-22)
```powershell
py -3 tests/test_energocampus.py
```
Тестовый набор проверяет позитивные и негативные сценарии, граничные значения, потерю связи `S0_OFFLINE`, дедупликацию пакетов телеметрии, целостность 14 таблиц БД, жизненный цикл рекомендаций (`new -> accepted -> completed / rejected`), защиту от SQL-инъекций и XSS, матрицу ролевого доступа RBAC для трёх ролей (`laborant`, `energomanager`, `sys_admin`), блокировку модифицирующих запросов в SQL-консоли, валидацию границ в `update_row`, аутентификацию ролей `/api/v1/auth/role` и метрики качества регрессионной модели (`MAE`, `RMSE`, `MAPE`, $R^2$).
